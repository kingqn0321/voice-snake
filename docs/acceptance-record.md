# 实机验收记录模板

本文件为待填写模板，不是已通过的测试报告。每个环境分别使用一份记录和一份 [60 条口令表](acceptance-samples.csv)，不要覆盖其他环境的结果。原始记录和录屏存入忽略目录 `test-results/acceptance/<环境ID>/`；经检查、去除隐私内容后的汇总写入测试报告。

## 环境

| 字段 | 实际值 |
| --- | --- |
| 日期、测试人、环境 ID（E01–E04） | 待填 |
| 操作系统完整版本、CPU、内存 | 待填 |
| 浏览器完整版本 | 待填 |
| 源码提交哈希、是否有未提交变更 | 待填，使用 `git rev-parse HEAD` 与 `git status --short` |
| 识别模式、模型配置 | 待填；本地默认 fast-v1，在线结果单独记录 |
| 麦克风型号、系统输入增益、距离 | 待填 |
| 网络、环境噪声与录屏帧率 | 待填 |
| 音画同步误差、发声结束标注方法 | 待填 |

## 口令记录

1. 使用普通入口，不加 `?debug=1`；选择识别模式并启动、授权。确认系统默认输入设备正确。
2. 按 CSV 的前置状态和方向准备每条样本；准备动作另计，不混入 50 条有效口令。蛇头保留足够空间，不把反向、同向或碰撞造成的规则拒绝算作识别失败。
3. 每条说一次，连续记录，不筛掉失败尝试。记录识别文本、页面命令和实际动作；3 秒无正确执行记超时，迟到结果不改判成功。
4. `actual_command` 记录实际动作类别，无动作填 `NONE`；`result` 填 `PASS`、`WRONG`、`TIMEOUT`、`DUPLICATE` 或 `NOT_RUN`。所有失败在 `notes` 解释，未测试项不得留作通过。
5. `confirm_ms`、`turn_ms` 按测试报告的 T0/T1/T2 标注，仅填成功且有证据的值。方向中间结果可能在说完前执行，因此允许负值；页面模块耗时不填入这两列。非方向样本的 `turn_ms` 留空。
6. 负样本无游戏动作才算通过。中间结果误触后又被最终文本纠正，仍记失败。每条 `evidence` 填录屏文件名和时间范围。

有效口令成功数须至少 48/50；负样本误触目标 0/10。按环境分别报告样本总数、未测数、失败原因与 nearest-rank 中位数/P95，不将不同模式或不同环境混合统计。完整统计定义见[测试报告](validation.md)。

## 汇总

填写单个环境的 CSV 后，可生成 Markdown 汇总。环境参数应包含系统、浏览器及识别模式；版本参数填写实际被测提交和工作区状态，不自动使用当前 HEAD。下面使用未填结果的模板演示命令，输出为未测，不能作为实测证据：

```sh
npm run --silent report:acceptance -- docs/acceptance-samples.csv --environment "E03 macOS Chrome 本地 fast-v1（模板演示）" --revision "未测试"
```

正式验收时，将输入路径替换为该环境已填写的 CSV，并填写真实环境、版本；可用 shell 重定向将输出保存为另一个 `.md` 文件。不同环境或识别模式分别运行，原 CSV 不会被修改。只有明确填写 `PASS` 才算通过，空结果及 `NOT_RUN` 均为未测；正确率分母为文件中的全部有效口令，包含未测项。文件须保留全部计划样本，不筛掉失败或未测行。

工具校验列名、重复 ID、结果、动作一致性和延迟格式；无效输入会报错并返回非零退出码。样本数不足 50/10 或仍有未测时不判断数量目标达标。仅成功且填写证据位置的测量值参与 nearest-rank 中位数/P95，负延迟保留，失败样本的延迟忽略。汇总会列出缺失证据、缺失延迟和失败原因；工具不检查视频内容、样本分配、连续三局或环境真实性，最终结论仍需人工复核。
